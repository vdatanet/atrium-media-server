## High

- [ ] **H1 · `tests/library/test_identity.py:203`** — a test that cannot fail.
  > `assert for_season(series, 0) == for_season(series, 0)`

  Two calls to the same pure function with identical arguments. `for_season(series_id,
  season_number)` takes no directory name, so the rename-invariance the test's name claims rests
  on the signature, which nothing here inspects — in one process this assertion cannot fail.
  Breaches the project's own standard ("a test that would pass against the bug is not a test") and
  the spirit of Principle VIII. Resolve: assert the signature carries no directory parameter (as
  `test_no_library_takes_part_in_a_by_name_identity` does), or derive the same season through two
  directory spellings via the resolver.

- [ ] **H2 · `specs/006-images/spec.md:227`** — a client-observable behaviour the spec asserts,
  nothing implements, no criterion covers and no accepted gap records.
  > "v1 **serves** chapter images that exist on disk. It does not **extract** them" …
  > "`GET .../Images/Chapter/{index}` serves the corresponding thumbnail"

  006 §5 never mentions `Chapter`. No v1 code path can create a chapter row —
  `tests/conformance/test_image_routes.py:612` (`test_no_v1_writer_can_create_a_chapter_row`)
  documents exactly that as a tripwire, and every chapter request answers the absent-image `404`.
  The behaviours accepted-gaps section has no chapter entry (its only two chapter mentions are the
  §1.11 error shape). This is the same shape as the historic 003 "directory emptied" finding.
  Breaches Principles III and VIII. Resolve: an accepted-gap entry in
  `compatibility/behaviours.md` §5 (closing mechanism: the feature that first writes chapter
  rows), plus an honesty edit to §3.5's "serves … that exist".
