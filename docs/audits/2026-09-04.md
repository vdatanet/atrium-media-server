documents against reality (B), tests that cannot fail (C), zero delta (D) and hygiene (E). Line

**Read this file the way `tasks.md` is read.** An unticked box is an open debt. The pull request
that resolves a finding ticks its box **in the same commit**, so the record and the repository
never disagree about what is still open. A finding that turns out to be wrong is not deleted: it is
ticked with a one-line note saying why it was wrong, because a refuted finding is a calibration
datum for the next audit.

every finding below, which is the reason they need a person. H1 is the exception in kind: if its
row is accurate then the code is wrong rather than the document, and that is settled by a

## High

- [ ] **H1 · `specs/001-server-identity-and-discovery/spec.md:163`** — a specified refusal that
  nothing implements, no criterion covers, and which may be a delta.
  > "| Valid token without permission | `403` |"

  `get_system_info` (`src/atrium/api/system.py:130-137`) gates on plain `require_user`: there is no
  permission check, no `403` path and no test. AC-5 says `/System/Info` answers "`200` with a valid
  one", which reads as the opposite of the row, so the criterion cannot be said to cover it even
  generously. The reference's route carries `Policy = FirstTimeSetupOrIgnoreParentalControl` and
  declares the `403`. Breaches Principle VIII, and — if the row is accurate — Principle I, since
  Atrium would be answering an account the reference refuses.

  **The row carries no citation**, which is why this cannot be fixed by reading. Measure whether
  the reference actually refuses; if it does, this is a missing check and a criterion, and if it
  does not, the row has been wrong since 001 was written and eleven features and three audits
  passed over it.

  > **Measured 2026-09-04 by C1, and the box stays unticked on purpose. It refuses.**
  > `tools/probe_system_info_permission.py` stood up a single-use instance of the pinned version
  > and read the whole 2x2 — caller on the LAN or off it, against an account holding the flag or
  > not `[probe: tools/probe_system_info_permission.py, Jellyfin 10.11.11, 2026-09-04]`.
  >
  > **The row is right that a `403` exists and wrong about what reaches it, and the correction
  > makes H1 larger rather than smaller.** There is no permission on this route.
  > `FirstTimeSetupOrIgnoreParentalControl` is `FirstTimeSetupRequirement(validateParentalSchedule:
  > false, requireAdmin: false)`, whose handler succeeds for both roles the reference issues a
  > token; the branch that would refuse needs the `Guest` role, and the authentication handler
  > gives that role to nobody. The refusal comes from the default handler underneath the policy, it
  > is `EnableRemoteAccess`, and it only fires from an address the server does not count as local —
  > proved rather than assumed, by `/System/Endpoint`'s own `IsInNetwork` reading `true` before the
  > instance's LAN was narrowed and `false` after. An account with **every** `Enable*` flag off is
  > answered `200` from the LAN. Remote and without the flag it is `403`, empty body, no content
  > type; remote **with** the flag, `200`. `/Users/Me` is refused identically, and so is an
  > **administrator** who lacks the flag, because the check runs ahead of the administrator bypass.
  >
  > **So closing this is not a check inside `get_system_info`.** It is a server-wide gate ahead of
  > every route that takes a token, plus a definition of "this server's own network" that v1 does
  > not have, landing in an already-`Implemented` feature — a Principle I scope call this project's
  > owner reserves, which is why C1 stopped here rather than implementing it. What C1 landed is the
  > probe, the citation the row never had, and the correction to the two documents the measurement
  > falsified: 001 §3.2's row now states the condition and says why no criterion accompanies it,
  > 002 §3.5's *"the unenforced flags all gate features v1 does not have"* now records the one that
  > does not, and behaviours §5's policy-flags row is narrowed to say that this delta is observable
  > rather than not. **What is owed is the decision**: implement the gate, or accept the divergence
  > deliberately in §4 and say what it costs. Ticking this box needs one of the two.
