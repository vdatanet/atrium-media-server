# Audit — 2026-09-01

The full `/audit` of the whole repository at `main` @ `a6cf3a5`, run 2026-09-01 immediately after
009 T14 merged and the feature was marked `Implemented`: provenance (family A), the documents
against reality (B), tests that cannot fail (C), zero delta (D) and hygiene (E). Line numbers refer
to the audited tree and are not maintained as fixes land — each finding's quote is the stable
locator.

**Read this file the way `tasks.md` is read.** An unticked box is an open debt. The pull request
that resolves a finding ticks its box **in the same commit**, so the record and the repository
never disagree about what is still open. A finding that turns out to be wrong is not deleted: it is
ticked with a one-line note saying why it was wrong, because a refuted finding is a calibration
datum for the next audit.

**Nothing in this audit is a bug in the code.** `ruff · mypy · pytest` is green on every finding
below, which is the reason they need a person: each one is a claim a document makes that the
repository no longer supports, and no gate in this project can see that class of drift.

**Findings: 1 high, 3 medium, 1 low — and the low is refuted.**

M3 is not a finding the audit *reported*. It was raised in the closing paragraph as an aside worth
a tidy-up, and turned out on a close reading — taken while fixing M1 — to be a document asserting
something false about the code rather than merely overstating a debt. It is recorded here at the
severity it deserved, not the one it was given, because the gap between the two is the audit's own
calibration error and the next audit should be able to see it.

## High

- [x] **H1 · `specs/002-authentication-users-and-sessions/spec.md:404`** — an observable delta lived
  in the repository as an open question, with no divergence entry and no argument.
  > "**Undecided:** whether this route follows §3.4 or keeps the refusal is a divergence to argue or
  > to withdraw, and neither was taken at a 009 task."

  Atrium answered `403` when a non-administrator read another user; 009 T2 had measured on
  2026-08-31 that the reference answers `200` with the whole object, `Configuration` and `Policy`
  included. That `403` had been stated in §3.7 **with no provenance** since 002 was written, and
  criterion 7 of §5 and the conformance matrix still asserted it. Breaches Principle I (zero delta)
  and Principle II. It is the same disclosure behaviours §3.5 already replicates on `/Users/Public`
  by a second road, so keeping the refusal on one road was also internally inconsistent.

  **Resolved by measurement, not by argument.** [#232](https://github.com/vdatanet/atrium-media-server/pull/232)
  widened the one measured cell to seven (`tools/probe_user_read.py`, creating and deleting two
  throwaway non-administrators): no cell refuses. The refusal was additionally **masking the
  route's two real error paths** — an absent user and a malformed identifier were both answered
  with it — which surfaced only once it was gone. behaviours §3.22 carries the entry, class B,
  replicated.

## Medium

- [x] **M1 · `specs/009-playlists/plan.md:752`** — §8's table of tests named a file that was never
  written.
  > "| 5, 6 | conformance + `tests/unit/test_playlists.py` | Duplicate on both paths; …"

  Reading the whole table for the fix found three more: it counted **nineteen** acceptance criteria
  where there are twenty, still called the move matrix the **25 rows this plan modelled** rather
  than the thirty T1 measured against the reference, and still planned a `404` for a request naming
  the playlist's owner — which is the 25-byte `403` `effective_user` answers everywhere, and which
  AC-15 was corrected to at T14. §6 had been kept current as each measurement landed and §8 had
  not. Breaches Principle III. A table of tests is the section most prone to this: nothing reads
  it, so nothing fails when it drifts.

- [x] **M2 · `docs/compatibility/reference-target.md:14`** — the API contract was pinned one patch
  version behind the behavioural reference.
  > "| API contract | Jellyfin `10.11.10` OpenAPI document |"

  Found already in flight: [#228](https://github.com/vdatanet/atrium-media-server/pull/228) measured
  that **nineteen names in the property-name index were never Jellyfin's**, and
  [#229](https://github.com/vdatanet/atrium-media-server/pull/229) moved the pin to 10.11.11 and
  gave the index a gate that needs no OpenAPI document present — which is why CI had never caught
  the staleness: the freshness step skipped when no document was there, which on the runner is
  always. Recorded here because `main` still carried it at `a6cf3a5`.

- [x] **M3 · `specs/002-authentication-users-and-sessions/spec.md:458`** — an open question
  reporting a debt that had been paid, on a premise that had stopped being true.
  > "the account available to measure with is an administrator, and an administrator lacks no
  > permission"

  and, in the same row, its deliverable:
  > "the **shape** of both `403`s, which v1 sends empty by analogy with the measured empty `401`"

  Three probes now create and delete throwaway non-administrators, so the premise is false; and
  009 T2 measured both shapes — a controller's own refusal is `text/plain` with no charset and 25
  bytes, an authorization **policy**'s has no body and no content type — so the shape is measured
  rather than analogised. The second quote describes code that has not existed since T2:
  `ForbiddenError` has answered the 25 bytes since, and `EmptyForbiddenError` is the second class.
  Breaches Principle III. Narrowed to the three refusals still genuinely open — a wrong password on
  an enabled account, a locked-out account, and a live token whose user was disabled after it was
  issued — which still cost somebody's account a lockout counter to measure.

## Low

- [x] **L1 · `tests/metadata/test_remote_refresh.py:547` — REFUTED.** Reported under C3 as a test
  that never runs on CI.
  > `pytest.skip("set ATRIUM_TMDB_API_KEY and ATRIUM_MUSICBRAINZ_CONTACT to run this")`

  It is not silently disabled. The test carries `@pytest.mark.needs_reference`, `pyproject.toml`
  declares that marker *"skipped by default, never in CI"*, and the docstring thirteen lines above
  the quote states the reason: *"Principle VII forbids a test that depends on network availability,
  which is why this is opt-in rather than skipped-when-offline: a test that quietly skips is a test
  that stopped running."* The `pytest.skip` fires only for somebody who asked for `-m
  needs_reference` without the credentials. **This is an accepted gap with a named mechanism, which
  this audit's own rules say is not a finding** — reported because the marker and the docstring
  were not read before the `skip` was. The calibration datum: a `grep` for `skip` produces exactly
  this false positive, and the guard against it is reading upward from the hit.
